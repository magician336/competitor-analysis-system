# CodeRadar 容器化部署与配置架构

> **核心原则**：容器化部署、配置统一集中、逻辑与数据分离

---

## 一、容器化部署：三服务 + 一前端

CodeRadar 以 **4 个 Docker 容器** 组成完整服务集群，所有服务由 `docker-compose.yml` 统一编排：

```
┌─────────────────────────────────────────────────────────────────┐
│                       Docker Compose                            │
│                                                                  │
│  外部请求                                                         │
│      │                                                            │
│      ▼                                                            │
│  ┌──────────────────────┐                                         │
│  │  frontend (nginx)    │  Vue 3 SPA，宿主端口 8080               │
│  │  反向代理 /api/* → api:8000                                   │
│  └────────┬─────────────┘                                         │
│           │  proxy_pass                                           │
│           ▼                                                        │
│  ┌──────────────────────┐    ┌──────────────────────┐             │
│  │  api (FastAPI)       │    │  worker (后台消费)    │             │
│  │  端口 8000 (容器内)  │    │  无端口暴露            │             │
│  │  宿主映射 → 8001     │    │                        │             │
│  │                      │    │  共享 SQLite 数据库    │             │
│  │  CORS → Auth →       │    │  共享 Mini-RAG 索引   │             │
│  │  RateLimit → Audit   │    │  共享模型缓存          │             │
│  │                      │    │                        │             │
│  │  ┌─ agents/ ───────┐ │    │  轮询 SQLite 领任务   │             │
│  │  │ Price/Product/  │ │    │  单例租约 + 心跳      │             │
│  │  │ Risk/Compare/   │ │    │  调用 Agent 编排器    │             │
│  │  │ Benchmark/      │ │    │  回写分支进度         │             │
│  │  │ Briefing/ReAct  │ │    │                        │             │
│  │  └─────────────────┘ │    └──────────────────────┘             │
│  └────────┬─────────────┘                                         │
│           │  depends_on (condition: service_healthy)               │
│           ▼                                                        │
│  ┌──────────────────────┐                                         │
│  │  elasticsearch:9.4.1 │  BM25 + 稠密向量                        │
│  │  端口 9200           │  读别名: coderadar_chunks_current       │
│  │  单节点, 2GB 内存    │  版本化物理索引 + 原子切换              │
│  └──────────────────────┘                                         │
└─────────────────────────────────────────────────────────────────┘
```

### 1.1 服务职责

| 服务 | 镜像 | 容器内端口 | 宿主端口 | 健康检查 |
|------|------|-----------|---------|---------|
| **elasticsearch** | `docker.elastic.co/elasticsearch/elasticsearch:9.4.1` | 9200 | 9200 | `_cluster/health?wait_for_status=yellow` |
| **api** | 项目 Dockerfile（`python:3.11-slim`） | 8000 | **8001** | `GET /health` 200 |
| **worker** | 项目 Dockerfile（`python:3.11-slim`） | 无 | 无 | 无 |
| **frontend** | `./frontend/Dockerfile`（nginx） | 80 | **8080** | 无 |

### 1.2 启动方式

```powershell
# 默认配置（hash 嵌入，rules 模式）
docker compose up -d --build

# 正式配置（BGE-M3 嵌入，需提前设 .env）
# 编辑 .env: MINIRAG_PROFILE=formal, MINIRAG_INSTALL_ML=true
docker compose up -d --build

# 单独重启某服务
docker compose restart api
docker compose restart worker

# 查看日志
docker compose logs -f api
docker compose logs -f worker
```

## 二、配置统一集中：单一入口，三层覆盖

所有配置以 **`.env` 文件为单一入口**，通过三层机制逐级覆盖，无需修改代码即可适配不同环境（开发/测试/正式部署）。

### 2.1 配置加载顺序

```
启动 → dotenv 加载 .env
    ↓
第 1 层：YAML 配置文件（config/）
    ├── competitors.yaml     ← 竞品 URL、来源、证据等级
    ├── dimensions.yaml      ← D1-D7 关键词规则
    ├── mini_rag.yaml        ← Mini-RAG 默认（hash）
    ├── mini_rag.formal.yaml ← Mini-RAG 正式（BGE-M3）
    ├── scoring.yaml         ← 能力快照评分权重
    └── codemate_baseline.yaml
    ↓
第 2 层：环境变量覆盖（.env → docker-compose → 容器）
    ├── MINIRAG_PROFILE      ← 一键切换 default ↔ formal
    ├── CODERADAR_AGENT_MODE ← rules / llm / hybrid
    ├── DEEPSEEK_API_KEY     ← LLM 密钥
    ├── CODERADAR_AUTH_*     ← 认证与限流参数
    └── ...
    ↓
第 3 层：代码默认值兜底（Pydantic field(default=...)）
    ├── EmbeddingSettings.provider = "hash"
    ├── RankingSettings.semantic_weight = 0.70
    └── IndexBuilder.bulk_batch_size = 200
```

### 2.2 关键配置开关：两个变量驱动全局行为

日常部署只需关心 **两个环境变量**：

| 变量 | 可选值 | 切换效果 |
|------|--------|---------|
| `MINIRAG_PROFILE` | `default` | hash 嵌入 + 词法重排，无模型依赖，开发/测试用 |
| `MINIRAG_PROFILE` | `formal` | BGE-M3 嵌入 + Cross-Encoder 重排，正式检索用 |
| `CODERADAR_AGENT_MODE` | `rules` | 离线规则，确定性基线，无需 LLM |
| `CODERADAR_AGENT_MODE` | `hybrid` | 在线 LLM 润色，推荐生产模式 |
| `CODERADAR_AGENT_MODE` | `llm` | 全程 LLM，需要 DEEPSEEK_API_KEY |

### 2.3 配置文件详解

**Mini-RAG 配置（两个 Profile）：**

```yaml
# config/mini_rag.yaml（default）         # config/mini_rag.formal.yaml（formal）
embedding:                                   embedding:
  provider: hash               ← vs →         provider: sentence_transformers
  dimension: 1024                              dimension: 1024
reranker:                                      reranker:
  provider: lexical            ← vs →         provider: cross_encoder
  strict: false                                strict: true
```

两个配置的检索参数相同（BM20 + Dense20 + RRF30 + Rerank20），仅向量化和重排序引擎不同。

**`config/scoring.yaml`：能力快照评分规则**

```yaml
evidence_share: 0.60        # 证据分占比
benchmark_share: 0.40       # 基准分占比
neutral_baseline: 50.0      # 无历史基线时的中性起点
evidence_level_weights:     # 证据等级权重
  A: 1.00  B: 0.82  C: 0.62  D: 0.36
freshness:                  # 时间衰减
  - max_days: 30    → weight: 1.00
  - max_days: 90    → weight: 0.85
  - max_days: 180   → weight: 0.65
  - max_days: null  → weight: 0.45
```

**竞品与维度配置：**

```yaml
# config/competitors.yaml - 5 个竞品固定
#   cursor / github_copilot / trae / tongyi_lingma / codegeex
#   每个竞品含 official / changelog / pricing / github / rss 来源

# config/dimensions.yaml - D1-D7 关键词规则
#   每维度 10-15 个中英文关键词，review_threshold: 0.55
```

### 2.4 `.env` 文件结构（配置的唯一入口）

```ini
# ── 核心开关 ──────────────────────────────────
MINIRAG_PROFILE=default         # default | formal
CODERADAR_AGENT_MODE=rules      # rules | llm | hybrid
MINIRAG_INSTALL_ML=false        # 是否安装 ML 依赖

# ── 密钥 ──────────────────────────────────────
GITHUB_TOKEN=                   # GitHub API 只读 token
DEEPSEEK_API_KEY=               # LLM 密钥（仅 llm/hybrid 需要）
CODERADAR_API_KEY=              # 认证密钥

# ── 认证与限流 ────────────────────────────────
CODERADAR_AUTH_ENABLED=true
CODERADAR_READ_RATE_PER_MINUTE=120
CODERADAR_WRITE_RATE_PER_MINUTE=30

# ── 端口 ──────────────────────────────────────
CODERADAR_API_PORT=8001
CODERADAR_UI_PORT=8080

# ── 路径（相对路径，容器内外一致）─────────────
CODERADAR_DATABASE_URL=sqlite:///data/runtime/coderadar.db
MINIRAG_DOCUMENTS_PATH=data/cleaned/documents.jsonl
MINIRAG_TRACE_PATH=data/runtime/retrieval_traces.jsonl
MINIRAG_MODEL_CACHE_DIR=.cache/models

# ── Worker 参数 ────────────────────────────────
CODERADAR_WORKFLOW_POLL_SECONDS=1
CODERADAR_WORKFLOW_LEASE_SECONDS=30
CODERADAR_WORKFLOW_HEARTBEAT_SECONDS=10
CODERADAR_WORKFLOW_TIMEOUT_SECONDS=300
```

## 三、逻辑与数据分离

### 3.1 完整分离模型

```
宿主文件系统                              Docker 容器
┌─────────────────────┐       ┌──────────────────────────┐
│  代码（版本控制）     │       │  逻辑（运行时代码）       │
│  ./Proj/             │──────▶│  /app/CodeRadar/         │
│    competitor-       │ 镜像  │    agents/               │
│    analysis-system/  │ 构建  │    backend/              │
│      agents/         │       │    mini_rag/             │
│      backend/        │       │    processing/           │
│      mini_rag/       │       │    schemas/              │
│      config/         │       │    config/               │
│      Dockerfile      │       │    ...                   │
│      ...             │       └──────────────────────────┘
│                      │
│  数据（持久化卷）     │       ┌──────────────────────────┐
│  ./data/             │──────▶│  /app/CodeRadar/data/    │
│    raw/ (不可变)      │ 绑定  │    raw/                  │
│    cleaned/          │ 挂载  │    cleaned/              │
│    runtime/ (命名卷) │       │    runtime/ (命名卷)     │
│    snapshots/        │       │    snapshots/            │
│    samples/          │       │    samples/              │
│                      │       └──────────────────────────┘
│  模型缓存（命名卷）   │       ┌──────────────────────────┐
│                      │──────▶│  /app/CodeRadar/         │
│                      │       │    .cache/models/        │
└─────────────────────┘       └──────────────────────────┘
```

### 3.2 三种卷类型

| 卷 | 类型 | 挂载点 | 内容 | 生命周期 |
|----|------|--------|------|---------|
| `./data` | **绑定挂载**（bind mount） | `/app/CodeRadar/data` | 采集原始数据、清洗产物、样本集 | 宿主机持久，容器删除不丢失 |
| `coderadar_runtime_data` | **命名卷**（named volume） | `/app/CodeRadar/data/runtime` | SQLite 数据库、检索轨迹、评测结果 | Docker 管理，`docker volume rm` 删除 |
| `coderadar_model_cache` | **命名卷**（named volume） | `/app/CodeRadar/.cache/models` | HuggingFace 模型权重（~2GB） | Docker 管理，避免每次构建重下载 |
| `coderadar_es_data` | **命名卷**（named volume） | `/usr/share/elasticsearch/data` | Elasticsearch 索引数据 | Docker 管理 |

### 3.3 数据目录结构

```
data/
├── raw/                         # 原始采集数据（不可变，版本控制）
│   ├── cursor/
│   │   ├── official/            #   官网页面 (.html + .meta.json)
│   │   ├── changelog/           #   更新日志
│   │   ├── pricing/             #   定价页
│   │   ├── github_release/      #   GitHub Release
│   │   ├── github_issue/        #   GitHub Issue
│   │   └── rss/                 #   RSS feed
│   ├── github_copilot/
│   ├── trae/
│   ├── tongyi_lingma/
│   └── codegeex/
│
├── cleaned/                     # 清洗产物（可从 raw 重放重建）
│   └── documents.jsonl          #   结构化文档（每行一个 JSON 文档）
│
├── runtime/                     # 运行时数据（命名卷，容器的临时产物）
│   ├── coderadar.db             #   SQLite 数据库（11 个 ORM 表）
│   ├── coderadar.db-wal         #   SQLite WAL 日志
│   ├── coderadar.db-shm         #   SQLite 共享内存
│   ├── retrieval_traces.jsonl   #   检索轨迹日志
│   ├── mini_rag_evaluation.json #   Mini-RAG 评测结果
│   ├── ai_precheck/             #   AI 数据预审核产物
│   └── ai_relevance/            #   AI 相关性预标注
│
├── snapshots/                   # 增量采集状态快照
│   └── http_cache.json          #   HTTP 缓存（ETag/Last-Modified）
│
└── samples/                     # 金标评测数据（版本控制）
    ├── 测试数据集.csv            #   50 个问题的金标评测集
    └── 评测集人工复核.csv        #   人工复核后的评测集
```

### 3.4 逻辑与数据分离的优势

| 场景 | 传统做法的问题 | 本项目的做法 |
|------|--------------|-------------|
| **代码升级** | 容器重建后数据丢失 | 数据在卷中，容器重建不丢失 |
| **多环境部署** | 每环境改代码配置 | `.env` 一份文件控制全部行为 |
| **数据重放** | 修改数据需重建镜像 | `raw` 不可变，`process --rebuild` 重放清洗 |
| **模型切换** | 修改代码改嵌入配置 | `MINIRAG_PROFILE=formal` 一键切换 |
| **数据安全** | 数据混在容器层 | `raw` 不可变、`runtime` 可丢、`samples` 版本控制 |
| **团队协作** | 每人维护一套本地配置 | `.env.example` + `.gitignore` 隔离本地配置 |

其中 `data/` 下的三类数据遵循不同的生命周期策略：

```
raw/        不可变 ← 一旦写入永不修改（重放时重建其上所有派生数据）
cleaned/    可重放 ← 通过 process --rebuild 从 raw 原子重建
runtime/    可丢弃 ← 容器删除后安全可删，通过 build_index 和 init_database 重建
samples/    版本化 ← 金标评测集，随代码提交
```

## 四、典型操作流程

### 4.1 首次部署

```powershell
# 1. 克隆代码
git clone <repo> && cd Proj/competitor-analysis-system

# 2. 配置环境
cp .env.example .env
# 编辑 .env：设置 GITHUB_TOKEN、CODERADAR_API_KEY、DEEPSEEK_API_KEY（如需）

# 3. 启动服务
docker compose up -d --build

# 4. 初始化数据库
docker compose exec api python -m scripts.init_database

# 5. 重建索引
docker compose exec api python -m scripts.build_index

# 6. 验证
curl http://127.0.0.1:8001/health
curl http://127.0.0.1:8080        # 前端页面
```

### 4.2 日常操作

```powershell
# 数据采集（新数据入 raw/）
docker compose exec api python -m scripts.data_pipeline all --competitors all --since-days 7

# 数据清洗（raw → cleaned）
docker compose exec api python -m scripts.data_pipeline process --rebuild

# 索引重建（cleaned → Elasticsearch）
docker compose exec api python -m scripts.build_index

# 更换配置模式
# 编辑 .env → MINIRAG_PROFILE=formal, MINIRAG_INSTALL_ML=true
docker compose up -d --build api    # 重建含 ML 依赖的镜像
docker compose exec api python -m scripts.build_index  # 全量重建索引
```

### 4.3 数据备份与恢复

```powershell
# 备份运行时数据
docker run --rm -v coderadar_runtime_data:/source -v D:\backups:/dest alpine \
  tar czf /dest/coderadar_runtime_$(date +%Y%m%d).tar.gz -C /source .

# 迁移到新环境
# 1. 新环境启动空服务
# 2. 恢复 runtime 卷
# 3. 重建索引（如果 ES 数据丢失）
docker compose exec api python -m scripts.build_index
```

## 五、架构决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| **配置入口** | `.env` 单一入口 | 减少心智负担，部署只需改一个文件 |
| **Profile 切换** | 环境变量驱动 | 不改代码、不改 YAML，`docker compose` 重启即生效 |
| **数据持久化** | 绑定挂载 + 命名卷 | 绑定挂载适合频繁读写的原始数据，命名卷适合运行时缓存 |
| **路径约定** | 相对路径，容器内外一致 | `data/runtime/coderadar.db` 在宿主机和容器内路径相同，调试方便 |
| **模型缓存** | 命名卷隔离 | BGE-M3 2GB 权重一次下载，容器重建不清除 |
| **Worker 独立** | 独立容器进程 | API 请求与后台分析解耦，Worker 出问题不影响 API 可用性 |
| **Raw 不可变** | 写后只读 | 保证数据可追溯、可重放、可审计 |

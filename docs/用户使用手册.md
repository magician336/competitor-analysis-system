# CodeRadar 用户使用手册

## 1. 系统入口

CodeRadar 提供命令行接口和 FastAPI（基于 Python 的 Web 应用程序接口框架）服务。命令行用于采集、处理、审计、索引和查询；HTTP（Hypertext Transfer Protocol，超文本传输协议）接口用于应用集成。

项目根目录为 `D:\26Spring\project\CodeRadar`。以下 PowerShell 命令均从该目录执行。

## 2. 环境检查

```powershell
Set-Location D:\26Spring\project\CodeRadar
& .\.venv\Scripts\python.exe -m scripts.data_pipeline doctor
```

`doctor` 检查 Python 3.11.9、项目虚拟环境、依赖、五个竞品配置、D1—D7 标签配置和数据目录。未配置 `GITHUB_TOKEN` 时会给出匿名 GitHub API（Application Programming Interface，应用程序编程接口）限额警告。

## 3. 补采和处理数据

先使用只读试运行查看任务：

```powershell
& .\.venv\Scripts\python.exe -m scripts.data_pipeline crawl `
  --competitors cursor,github_copilot `
  --sources pricing,status_page,community,github_issue `
  --since-days 120 `
  --dry-run
```

确认任务后执行采集，再从全部原始响应重建结构化数据：

```powershell
& .\.venv\Scripts\python.exe -m scripts.data_pipeline crawl `
  --competitors cursor,github_copilot `
  --sources pricing,status_page,community,github_issue `
  --since-days 120 `
  --max-issues 100 `
  --max-comments 20 `
  --force

& .\.venv\Scripts\python.exe -m scripts.data_pipeline process --rebuild
& .\.venv\Scripts\python.exe -m scripts.audit_documents
```

采集命令写入 `data/raw`，处理命令读取 `data/raw` 并写入 `data/cleaned/documents.jsonl`。原始响应承担审计、重新清洗和规则重建职责；Mini-RAG 索引只读取结构化文档。

## 4. 构建检索索引

```powershell
docker compose up -d elasticsearch
& .\.venv\Scripts\python.exe -m scripts.build_index
```

全量构建会创建新的版本化物理索引，并在写入成功后切换读取别名 `coderadar_chunks_current`。当前本机存在一个包含 3,337 个 Chunk 的新物理索引，但读取别名仍指向包含 2,688 个 Chunk 的索引。使用当前 1,003 个文档版本查询前，应执行一次全量构建并检查别名状态。

```powershell
Invoke-RestMethod http://127.0.0.1:9200/_cat/aliases/coderadar_chunks_current?v
Invoke-RestMethod http://127.0.0.1:8000/api/rag/index/status
```

## 5. 查询证据

命令行查询示例：

```powershell
& .\.venv\Scripts\python.exe .\rag_query.py `
  'Cursor 最近有哪些 Agent 能力更新' `
  --competitor Cursor `
  --event-types product_release `
  --top-k 8
```

返回结果包含 `query_id`、解析后的过滤条件、证据列表、冲突列表和检索轨迹。每条证据保留 URL（Uniform Resource Locator，统一资源定位符）、Chunk 标识、文档和版本标识、字符区间、证据等级及排序分数。

## 6. 启动接口服务

```powershell
docker compose up -d --build
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/ready
```

当前 CodeRadar 主体服务公开系统健康接口和 `/api/rag` 路由。查询示例：

```powershell
$body = @{
  question = 'GitHub Copilot 最近的价格变化'
  competitor = 'GitHub Copilot'
  event_types = @('pricing_change')
  top_k = 8
} | ConvertTo-Json

$response = Invoke-RestMethod `
  -Method Post `
  -Uri http://127.0.0.1:8000/api/rag/query `
  -ContentType 'application/json; charset=utf-8' `
  -Body $body
$response
```

## 7. 复核引用

使用查询返回的 `query_id` 和证据 Chunk 标识提交引用验证。引用内容必须来自同一次查询的证据白名单，并与 URL、字符范围和原文一致。

```powershell
$validation = @{
  query_id = $response.query_id
  citations = @(
    @{
      chunk_id = $response.evidence[0].chunk_id
      quote = $response.evidence[0].quote
      url = $response.evidence[0].url
    }
  )
} | ConvertTo-Json -Depth 6

Invoke-RestMethod `
  -Method Post `
  -Uri http://127.0.0.1:8000/api/rag/citations/validate `
  -ContentType 'application/json; charset=utf-8' `
  -Body $validation
```

## 8. 常见状态

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| `/health` 返回 `ok` | API 进程存活 | 继续检查 `/ready` |
| `/ready` 返回 `ready` | 别名存在且向量模型兼容 | 可以查询当前别名 |
| `/ready` 返回 `degraded` | 索引缺失、后端异常或向量不兼容 | 检查 Elasticsearch、配置和索引映射 |
| 查询证据为 0 条 | 当前过滤条件无命中 | 检查竞品、事件、时间窗和数据覆盖 |
| `needs_review=true` | 规则标签需要人工确认 | 查看原始响应、正文和标签理由 |

`ready` 表示服务能够查询当前别名，不表示别名已经覆盖最新的 `documents.jsonl`。数据更新后还需要比对结构化数据哈希、索引版本和 Chunk 数量。

# CodeRadar 能力评分规则

## 1. 适用范围

能力评分用于 `update` 工作区中的能力快照与跨产品比较。CodeRadar 主体仓库提供事件标签、能力标签和可追溯证据，不在 Mini-RAG 检索阶段生成产品总分。评分配置位于 `update/config/scoring.yaml`，当前版本为 `week3-evidence-v2`。

## 2. 输入对象

评分以情报卡片和基准运行作为输入。情报卡片提供竞品、事件类型、D1—D7 能力维度、影响方向、影响幅度、证据等级、证据时间和置信度。基准运行提供任务是否成功、测试通过率、编译状态、危险行为和人工干预次数。

证据等级权重如下表。A 级代表官方一手证据，B 级代表可核验的高可信来源，C 级代表辅助来源，D 级代表线索。

| 证据等级 | 权重 |
| --- | ---: |
| A | 1.00 |
| B | 0.82 |
| C | 0.62 |
| D | 0.36 |

该权重参与证据置信度计算。权重不会替代原始引用；能力快照仍保留用于复核的 Chunk 标识。

## 3. 时效权重

证据时效依据证据时间与快照日期的间隔计算。

| 距快照日期 | 时效权重 |
| --- | ---: |
| 30 天以内 | 1.00 |
| 31—90 天 | 0.85 |
| 91—180 天 | 0.65 |
| 180 天以上或无更近分档 | 0.45 |

时效权重使近期事件在同等级证据中获得更高贡献。没有可评分证据的维度标记为 `insufficient_evidence`，不填充推测分数。

## 4. 维度分数

首个能力快照以 50 分中性基线计算有证据的维度。事件影响方向与幅度按照每级 4 分形成证据侧变化量，结果限制在 0—100 分。基准证据存在时，维度结果按下式组合：

```text
维度分数 = 0.60 × 证据侧分数 + 0.40 × 基准侧分数
```

基准侧分数由任务成功、测试通过和编译成功构成：

```text
基准侧基础分 = 0.55 × 任务成功 + 0.30 × 测试通过率 + 0.15 × 编译成功
```

危险行为扣 30 分；每次人工干预扣 2 分，人工干预累计扣分上限为 16 分。缺少正式基准运行时，快照只使用证据侧信息并记录覆盖率。

## 5. 覆盖率与排名门槛

跨产品矩阵的正式排名要求加权已评分维度覆盖率达到 0.80。低于门槛的产品保留分项结果并标记为不可排名。趋势比较还要求当前快照和前序快照的可比覆盖率达到 0.80。

当前保存的跨产品比较制品中，CodeMate Campus 基线覆盖率为 0，`official_ranking_ready=false`。因此该制品不能用于正式的我方产品差距排名。它可以展示已有竞品维度分数、证据覆盖和缺口状态。

## 6. 优先级与风险等级

情报卡片的优先级由事件影响、紧迫性、证据置信度和产品相关性组成。风险等级再根据优先级与是否存在证据划分。无证据卡片使用 0.12 的低置信度，并进入复核状态。

评分输出必须同时展示分数、覆盖率、置信度、证据数量、评分版本和快照标识。单独展示总分会隐藏缺失维度和证据不足，不能作为正式比较依据。

# CodeRadar 程序架构文档

> **产品名**: CodeRadar（Model Intelligence Observatory）  
> **竞品分析系统**: 采集 AI 编程助手（Cursor、GitHub Copilot、Trae、通义灵码、CodeGeeX）的多源数据，通过 Mini-RAG 混合检索 + LangChain Multi-Agent 生成情报卡片、能力快照、基准对比与 Markdown 简报。

---

## 二、六层架构详解

### 第 1 层：数据采集层（crawler/）

| 组件 | 文件 | 职责 |
|------|------|------|
| **CrawlOrchestrator** | `orchestrator.py` | 读取 `config/competitors.yaml`，编排所有采集任务 |
| **HTTP Client** | `http_client.py` | ETag/Last-Modified 条件请求、按域名限速、15s 超时、3 次指数退避、遵守 robots.txt |
| **Browser Renderer** | `browser_renderer.py` | Playwright 无头浏览器渲染 JS 动态页面 |
| **Official 采集器** | `crawl_official.py` | 采集竞品官网首页、功能介绍等静态页面 |
| **Changelog 采集器** | `crawl_changelog.py` | 采集更新日志（最大采集器，47K） |
| **Pricing 采集器** | `crawl_pricing.py` | 采集定价页面 |
| **GitHub 采集器** | `crawl_github.py` | 采集 GitHub Release / Issue |
| **RSS 采集器** | `rss_loader.py` | 解析 RSS feed |
| **Storage** | `storage.py` | 原始响应不可变存储到 `data/raw/<competitor>/<source>/` |

**输入**: 5 个竞品的 URL 配置  
**输出**: `data/raw/` 下的原始 HTML/JSON + `.meta.json`（不可变，可重放）

---

### 第 2 层：数据处理层（processing/）

| 组件 | 文件 | 职责 |
|------|------|------|
| **ProcessingPipeline** | `pipeline.py` | 管线编排：raw → cleaned documents.jsonl |
| **Cleaners** | `cleaners.py` | 每个竞品专属清洗器（去除广告/页脚/导航，52K 最大文件） |
| **Normalizers** | `normalizers.py` | URL 规范化、Unicode 归一化、空白标准化、SHA-256 哈希 |
| **Deduplicator** | `deduplicator.py` | 按竞品+来源+规范 URL+内容哈希去重 |
| **VersionStore** | `versioning.py` | 内容变化时关闭旧版本有效区间（保留历史版本） |
| **RuleLabeler** | `labeling.py` | 关键词规则打标 D1–D7 能力标签 + E1–E3 事件标签 + 证据等级 A–D |
| **Audit** | `audit.py` | 文档级别审计 |

**输入**: `data/raw/` 原始数据  
**输出**: `data/cleaned/documents.jsonl`（结构化文档，每行 JSON）

**D1–D7 能力维度**:
| 编码 | 维度 | 含义 |
|------|------|------|
| D1 | code_intelligence | 代码智能与补全、生成能力 |
| D2 | agent_context | 上下文感知与 Agent 任务能力 |
| D3 | ide_ecosystem | IDE 生态集成与插件体验 |
| D4 | model_extensibility | 模型可扩展性与多模型支持 |
| D5 | performance_cost | 性能与成本效益 |
| D6 | security_compliance | 安全合规与企业级能力 |
| D7 | education_fit | 教育场景适配与学习辅助 |

**E1–E3 事件类型**:  
- E1: pricing_change（价格变化）  
- E2: product_release（产品发布）  
- E3: risk_experience（风险事件）

**证据等级 A–D**: A=官网一手 → B=GitHub Release → C=Issue → D=线索

### 第 3 层：Mini-RAG 检索引擎层（mini_rag/）

Mini-RAG 是系统的检索核心，提供 **可验证的混合检索** 能力：

```
                             用户查询
                                │
                     ┌──────────┴──────────┐
                     │    QueryParser       │
                     │  竞品识别 · 时间窗口  │
                     │  维度筛选 · 版本判断  │
                     └──────────┬──────────┘
                                │
                     ┌──────────┴──────────┐
                     │    QueryRewriter     │ (可选 LLM 扩展)
                     └──────────┬──────────┘
                                │
              ┌─────────────────┼─────────────────┐
              ▼                 ▼                 ▼
    ┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
    │  BM25Retriever  │ │  DenseRetriever │ │  ExactMatch     │
    │ (词法稀疏检索,  │ │ (句向量稠密检索, │ │  (精确匹配)     │
    │  20 candidates) │ │  20 candidates)  │ │                 │
    └────────┬────────┘ └────────┬─────────┘ └────────┬────────┘
              └────────────────┬──────────────────────┘
                               ▼
                    ┌─────────────────────┐
                    │   HybridRetriever   │
                    │   RRF 融合 (k=60)   │
                    │   取 30 candidates  │
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │   RankingPipeline   │
                    │ ┌─────────────────┐│
                    │ │ Reranker        ││ ← Cross-Encoder / 词法重排
                    │ │ (20 candidates) ││
                    │ └─────────────────┘│
                    │ ┌─────────────────┐│
                    │ │ TemporalRanker  ││ ← 时间衰减（半衰期 180 天）
                    │ └─────────────────┘│
                    │ ┌─────────────────┐│
                    │ │ EvidenceRanker  ││ ← 证据等级加权
                    │ └─────────────────┘│
                    │ 权重:语义0.70+时间 │
                    │ 0.12+版本0.08+证据 │
                    │ 0.10（必须归一化）  │
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │   CitationBuilder   │ ← 构建原文引用
                    │   CitationValidator │ ← 校验 chunk 存在
                    │   ConflictDetector  │ ← 跨 Agent 冲突检测
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │   RAGResponse       │
                    │   Chunk[] +         │
                    │   Evidence[] +      │
                    │   Conflict[]        │
                    └─────────────────────┘
```

#### 分块策略（ChunkingDispatcher）

按来源类型选择不同的分块器：

| 来源类型 | 分块器 | 策略 |
|---------|--------|------|
| official_page / official_changelog | OfficialChunker | 按标题层级分块 |
| github_release / github_issue | GitHubChunker | 按发布/Issue 边界分块 |
| pricing | PricingChunker | 按定价表格/套餐分块 |
| rss | RssChunker | 按条目分块 |

参数：目标 1200 字符、最大 1800 字符、重叠 160 字符、最小 80 字符。  
每个 Chunk 携带：document_id / version_id / chunk_id / 字符区间 / 标题路径 / 来源 / 时间 / 版本 / 事件标签 / 能力标签 / 证据等级。

#### 向量化（Embedding）

两套隔离的向量空间（不可混用）：

| 模式 | Provider | 模型 | 维度 | 用途 |
|------|---------|------|------|------|
| **hash**（默认） | `hash_embedding.py` | 确定性哈希 | 固定 | 离线开发/测试 |
| **bge-m3**（正式） | `sentence_transformer.py` | BAAI/bge-m3 | 1024 | 正式检索评测 |

#### Elasticsearch 索引管理

- 物理索引命名：`coderadar_chunks_{timestamp}`（每次全量重建生成新索引）
- 读别名：`coderadar_chunks_current`（原子切换）
- `IndexManager`：管理版本化物理索引 + 原子读别名切换
- `IncrementalIndexer`：幂等增量同步

#### Agent 三大运行模式

| 模式 | CODERADAR_AGENT_MODE | 说明 |
|------|---------------------|------|
| 离线规则 | `rules` | 确定性规则，不调 LLM，适合测试/演示 |
| 混合 | `hybrid` | 推荐在线：LLM 润色 + 非法回退到规则 |
| LLM | `llm` | 全程 LLM 分析 + RAG 白名单 + 确定性评分 |

#### 证据守卫机制

每个 Agent 都内置证据守卫：
1. 检索文本被视为不可信数据，Prompt 隔离其中指令
2. 模型只能引用本次检索白名单内的 `chunk_id`
3. 模型不能决定卡片 ID、证据对象、优先级公式或预警等级
4. 模型输出再次过完整 Pydantic 校验
5. 无证据结果降低置信度与优先级并标 `review_required`

#### 输出产物

| 产物 | 类型 | 说明 |
|------|------|------|
| IntelligenceCard | 情报卡片 | 按事件聚合，每条发现引用 `chunk_id`，含优先级/置信度/预警等级 |
| CapabilitySnapshot | 能力快照 | D1–D7 维度评分（证据分60%+基准分40%），覆盖率门槛 |
| ComparisonMatrix | 对标矩阵 | 跨产品 D1–D7 对比矩阵，含 N/A 单元/增长/差距推断 |
| BenchmarkRun | 基准评测 | 任务指纹 + 逐行错误隔离 + 原子 CSV |
| Briefing | 简报 | Markdown 格式可审阅报告 |

### 第 5 层：后端服务层（backend/）

#### 5.1 中间件栈（按执行顺序）

```
请求进入 → CORS 中间件 → API 安全与审计中间件 → JSON Charset 中间件 → 路由分发
```

| 中间件 | 功能 |
|--------|------|
| **CORSMiddleware** | 允许前端 `localhost:5173` 跨域 |

#### 5.4 异步工作流 Worker

`backend/workflow_worker.py` 是独立的 Worker 进程（Docker Compose 的 `worker` 服务）：

```
Worker 启动
    → 轮询 workflows 表（单例租约 + 心跳 10s）
    → 领取 pending 状态工作流（CAS 更新租约）
    → 调用 MultiAgentOrchestrator.run_attempt()
    → 实时回写每个分支进度（workflow_branch_attempts）
    → 完成/失败后更新 workflows 状态
    → 支持取消 / 超时(300s) / 重试(最多 3 次)

```



#### 5.5 用户认证子系统



用户认证系统提供完整的登录注册与会话管理：



| 组件 | 文件 | 职责 |

|------|------|------|

| **JWT 签发/验证** | `backend/auth.py` | 密码哈希（bcrypt）、JWT 令牌生成与校验、`require_user`/`require_admin` 依赖注入 |

| **认证路由** | `backend/routers/auth.py` | `POST /api/auth/register`、`/login`、`/logout`、`GET /me` |

| **认证 Schema** | `schemas/auth.py` | `RegisterRequest`、`LoginRequest`、`AuthUser` Pydantic 模型 |

| **种子脚本** | `backend/seed_demo_users.py` | 初始化两个演示账号（`coderadar_test1`/`coderadar_test2`） |

| **历史记录模型** | `schemas/history.py` | 查询历史 Pydantic 模型 |



会话流程：



```

浏览器 → POST /api/auth/login (username + password)

    → 服务端验证密码 (bcrypt)

    → 签发 JWT (含 user_id, is_admin, exp)

    → 设置 HttpOnly Cookie `session`

浏览器 → 自动携带 Cookie → 后续请求

    → 路由层 require_user 解析 JWT → 注入 AuthUser

    → 路由层 require_admin 校验 is_admin → 允许管理接口

```

## 七、关键设计决策

1. **两套向量空间隔离**：hash（离线确定性）与 BGE-M3（正式）不可混用，切换必须全量重建索引
2. **Raw 数据不可变**：原始采集数据永久保留，处理层可随时重放重建
3. **证据可追溯**：每条 Agent 结论必须引用 `chunk_id` + 原文片段 + 来源 URL，无证据不置信
4. **模式安全**：`rules` 模式运行真实 LCEL 但不调远程模型，适合无密钥演示
5. **前端的 CRUD 只调用 `formal_api.py`**：这是前端唯一的 API 面，其他路由是后台/调试接口
6. **Worker 独立进程**：API 服务与 Worker 共享代码镜像但进程隔离，Worker 持单例租约
7. **5 个竞品 ID 固定**：`cursor` / `github_copilot` / `trae` / `tongyi_lingma` / `codegeex`
8. **权重归一化校验**：Ranking 权重 semantic 0.70 + temporal 0.12 + version 0.08 + evidence 0.10 在构造时校验必须和为 1

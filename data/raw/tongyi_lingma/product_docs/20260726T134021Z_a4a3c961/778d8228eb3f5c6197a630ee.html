0.5.0（2026-07-15）

控制台 Forward Mode 与体验增强

新增

  • 控制台支持切换到 Forward Mode，并按模式展示独立导航

  • 控制台新增 Forward 模板调试器：支持创建调试会话、发送消息、上传附件、查看事件流并处理工具审批

  • 控制台新增可观测概览：展示活跃 Session、成功率、Token / Credit 消耗、7 日趋势与明细

  • 控制台新增用量与额度展示：支持查看月度用量、预算剩余、今日消耗和维度级变化

  • Memory Store 支持 Agent 读写，Agent 在执行任务的同时可以主动整理和维护记忆内容，把关键信息沉淀到记忆中并在后续任务里复用，让 Agent 的上下文积累更连贯

  • Agent 支持原生图片识别，可直接理解和读取对话中的图片内容，图片识别与读取效率更高，让涉及图片的任务处理更顺畅

0.1.0（2026-07-07）

Forward Mode 正式发布：面向企业终端用户的 Agent 交付

新增

  • Forward Mode 正式发布：调用方只需 template_id + identity_id，即可向终端用户交付预配置的 Agent

  • Forward Template 与 Identity：管理员预设 Agent 模板，为每位终端用户注入个性化配置（工具、Skill、文件、记忆库、环境变量），并自动隔离记忆与权限

  • Forward Schedule：支持 cron、一次性与手动触发，到点自动执行，执行结果可推送至 IM 渠道

  • Forward Channel：内建钉钉、飞书、企微、微信、Slack 等 IM 集成，支持消息收发、扫码绑定、审批与文件接收

  • Forward Schedule：支持自然语言创建、查询和删除定时任务；监控类任务可设置开始与停止时间

  • Forward Channel：新增 Lark 渠道，覆盖扫码注册、长连接会话、消息发送与流式卡片更新

  • Forward Channel：支持按区域配置可用渠道与用户配额

  • Forward Identity / Channel：Identity 删除或 Template 归档后，Runtime Channel 自动归档并停止相关会话

优化

  • 增强 Forward 模式的企业集成稳定性与输入校验，降低接入门槛

  • Forward Schedule：公平调度与失败自动恢复，高并发场景下运行更稳定

  • Forward Schedule：调度参数支持热更新，无需重启即可生效

  • Forward Schedule：自然语言创建任务时，信息不足会引导用户补充必要条件

  • Forward Channel：强化 Runtime Channel 安全性与用户归属校验，减少凭据暴露

  • Forward Channel：优化审批与流式卡片体验，降低多会话审批串线风险

事件驱动 + 视觉能力，让 Agent 更主动

  • 文件上传支持图片、文档、压缩包、音视频等更多格式

优化

  • MCP 服务器配置新增「交互策略」选项

  • 技能中心支持多选 + 一键批量导入，快速装配 Agent 能力

  • Session 详情页新增 Agent / Environment / Vault 分页，关联资源一目了然

0.0.7（2026-06-30）

CloudUse 上线：让 Agent 以机器身份把云用起来

本次升级围绕「Cloud Use」核心命题：Agent 不再只是对话助手，而是能以机器身份安全调用云 API、自主完成云上任务的自动化单元。配合诊断助手和 Session 动态 Patch，开发者从装配到调试的全链路效率大幅提升。

Cloud Use — 一次派活，云上闭环

Cloud Use—让「用云」不再必须有人在场。一次派活，云上闭环让 Agent 以机器身份，安全、完整地把云用起来。把技能市场、MCP 凭据库、Agent 装配整合进一个Agent。

  • 技能市场导入：浏览 Qoder 技能中心，支持分类筛选、阿里云专区与多选批量导入，常驻底部操作栏让你随时确认与提交

  • MCP 凭据管理：从 Vault 凭据库挑选 MCP 服务器，按服务折叠分组、按需懒加载，OAuth 接入提供向导式引导（含阿里云 Cloud Use 专项流程）

  • 一步式装配：导入技能 → 配置 MCP 权限 → 创建 Agent，全程在同一界面完成

诊断助手

Session 运行卡住、报错、行为异常时，不用再翻日志拼上下文。诊断助手帮你在控制台内完成「定位 → 归因 → 给建议」全流程。

  • 实时诊断：自动识别报错、推断根因，并给出可执行的修复建议

  • 一键拉取上下文：events、turns、tool_calls 自动收集，作为诊断输入，省去手动导出

  • 结论可分享：诊断结果支持导出、复制与分享，方便贴进工单或同步给团队

Session 动态 Patch

运行中的 Session 现在可以直接改配置，不再需要 archive 旧 session、重建新 session 来试一个想法。

  • 配置即时下发：支持 PATCH tools、mcp_servers

  • 下一轮 turn 立即生效：无需重启会话，无需中断当前任务上下文

  • 典型场景：A/B 调试 prompt、临时给 Agent 加个工具、切换模型对比效果

优化

  • MCP 工具选择器支持折叠分组、懒加载与类型筛选，长列表也能快速定位

  • 技能包下载改为浏览器原生下载，规避跨域兼容问题

  • Self-hosted 模式不再强制注入 workdir，改为相对路径提示，更贴近本地工程习惯

  • Deployment 创建与运行体验优化：资源配置预填充、初始事件块正确展示

  • 技能中心导入按钮常驻底部操作栏，多选场景下确认动作不再需要滚动找按钮

  • 环境列表为 self_hosted 类型补显「自托管」标签，环境归属一眼可见

0.0.6（2026-06-18）

本次升级让 Agent 从「云端单一执行环境」进化为「自带基础设施 + 内网工具互通 + 可编程环境初始化」的开放体系。

自托管沙箱

在你自己的基础设施上运行 Agent 工具执行，LLM 推理留在云端。代码、文件系统和网络出口完全在你的控制范围内，满足数据合规与内网访问需求。

  • 创建 self_hosted 类型 Environment，Worker 通过 Work Queue 协议监听并执行任务

  • 支持 Go SDK、CLI 和任意语言的 HTTP 直接对接

MCP 连接器

通过 Connector 将内网网络中的 MCP 服务器安全可靠地传递给 Cloud Agent，无需将内网服务开放到公网。

  • 创建 Tunnel → 启动 Connector（SSE 反向连接）→ Session 绑定 tunnel_id，三步完成

  • 域名白名单 + IP 级 SSRF 防护，安全边界清晰

  • 多实例水平扩展，单 Tunnel 支持多 Connector 负载均衡

自定义初始化脚本

在执行 Agent 工具前运行自定义初始化脚本，可用于安装依赖、预配置环境、拉取资源或注入凭证，在每个 Session 首次工具调用前自动执行一次。

优化

  • 工具执行耗时展示改为基于 wall-clock 锚点计时，避免流式渲染导致的计时跳变

0.0.5（2026-06-14）

本次升级让 Agent 从「单次对话单个角色」进化为「多角色协作 + 跨会话记忆 + 定时自动执行」的完整体系。

多 Agent 协作

单次会话中可调度多个 Agent 协同工作，每个 Agent 在独立线程中执行，通过 Mailbox 机制交换消息。适合将复杂任务拆分为「调研 + 编码 + 测试」等多角色流水线，无需手动编排。

环境变量

创建会话时可传入自定义环境变量（键值对），Agent 在 Sandbox 中直接通过 $ENV_NAME 使用。适合注入数据库连接串、API Key 等运行时配置，无需写死在代码或系统提示词中。

Dreaming（智能记忆）

会话结束后，平台自动回顾对话内容，提取关键信息写入 Memory Store。下次同一 Agent 启动时自动加载已有记忆，实现跨会话持续积累上下文——用得越多，Agent 越了解你的项目。

定时任务（Deployments）

支持通过 cron 表达式配置定时触发，也可手动一键执行。提供完整生命周期管理：暂停 / 恢复 / 归档 / 自动重试 / 连续失败自动暂停。适合日报生成、定时巡检、数据同步等周期性场景。

0.0.4（2026-06-10）

本次升级 Cloud Agents 主线围绕「让 Agent 的输入更顺、模型更自由、工具更可控、体验更稳」做了一轮集中升级，涵盖四大主题：GitHub 仓库接入、新模型透出、自定义 Agent 工具支持，以及一批问题修复与体验优化。

GitHub 仓库接入

  • 创建会话时可直接挂载 GitHub 仓库作为会话资源，无需先 clone 到本地再上传，省一步是一步。

  • 创建会话页面新增内联 GitHub Personal Access Token 输入入口，私有仓库即填即用，凭证仅本次会话生效，不再依赖独立的凭证库配置。

新模型透出

  • 一次性接入 Qwen、DeepSeek、GLM、Kimi、MiniMax 等多家主流模型，并以 ${price_factor}x 统一展示积分倍率，方便挑选适合任务的模型与成本档位。 

自定义 Agent 工具支持

  • Agent 配置支持声明 type: custom 的自定义工具，由客户端实现执行逻辑，让 Agent 能力可以按业务场景自由扩展，不再局限于内置工具集。

  • 工具权限新增三档策略：always_allow 自动放行、always_ask 执行前请求用户确认、always_deny 直接拒绝，「人在回路」首次落地，敏感动作可强制人工确认后执行。

  • MCP 工具支持按 server 前缀整体授权，配置一次即可放行该 server 下所有工具，告别一项一项勾选。

问题修复 & 体验优化

  • 会话事件列表支持游标分页与滚动加载，超过 100 条事件不再被截断丢失。

  • 文件列表按创建时间倒序展示，最新文件置顶；新增「用途 / 状态 / File ID」列与一键复制。

  • SSE 实时事件流支持 Last-Event-ID 断点续传，网络抖动重连后自动续接，无需手动刷新。

  • 会话列表 10 秒轮询不再导致整页闪烁；事件区拥有独立滚动条，不再误带动整页滚动。

  • Agent 编辑模式的技能展示与详情页完全一致；技能数达到 20 上限时，前端友好提示并前置拦截，避免提交失败。

  • 中文输入法组词期间按回车不再误发消息；文件挂载路径不再出现 /data/data 双前缀。

  • 工单反馈支持图片上传与一键截屏，入口移至设置菜单，反馈链路更顺手。

  • 取消过程中卡死的会话会自动恢复；并发添加资源走 FOR UPDATE 锁，杜绝资源相互覆盖。

  • Skills 上传 zip 包时自动归一化 Windows 反斜杠路径，Mac / Windows 跨平台行为一致。

0.0.3（2026-06-09）

Hello, World!

我是 Cloud Agents CN，很高兴遇见你。

我是一个全托管的 AI Agent 云服务，自带推理执行引擎和工具运行环境，会持久化存储任务对话和文件历史。通过「大脑」与「双手」分离的架构，可以在保证数据安全的前提下，管理任意执行环境。开发者只需通过 REST API 调用，就能快速构建持续运行、自主进化的 Agent 应用——不必自建基础设施，不必维护沙箱，不必担心模型升级。

下面是我们可以一起做的事。

声明式 Agent，一次定义、长期演进

通过 Agent API 声明式创建和管理 Agent——配置模型、工具、系统指令、MCP 集成。支持版本管理与回滚，平台升级模型与编排策略时，已接入的应用零代码变更自动变强。

长程任务，跑得稳、续得上

长会话持续运行：跨小时到跨天的连续执行，支持断点恢复、事件流跨轮次持久化。会话事件实时流支持网络抖动后自动重连并从断点续传，全程无需刷新。

托管的执行环境，开箱即用的工具集

平台提供安全隔离的 Sandbox 执行环境，可配置网络策略，无需自建基础设施。内置 8 种开箱即用工具：bash、read、write、edit、glob、grep、web_fetch、web_search。需要更多能力时，可以接入外部 MCP Server 获得无限扩展。

全程可观测，每一步都看得见

通过 SSE 实时事件流，Agent 的每一步思考、每一次工具调用都会实时推送，方便观测、审计和回放。

完整的资源管理 API

  • 文件上传与挂载（Files API）：向 Session 提供文件上下文，Agent 产物也可通过 API 下载

  • 用户凭证（Vaults API）：安全托管访问凭证，Session 运行时按需注入

  • Agent Skills（Skills API）：为 Agent 附加领域专业知识，让通用 Agent 在特定任务上表现得更专业

  • 持久化记忆（Memory Stores API）：让 Agent 的学习成果与产出跨 Session 持久保留

核心 API 端点

  • POST /v1/cloud/agents — 创建 Agent

  • POST /v1/cloud/environments — 创建执行环境

  • POST /v1/cloud/sessions — 创建 Session（绑定 Agent + Environment）

  • POST /v1/cloud/sessions/{id}/events — 发送消息

  • GET /v1/cloud/sessions/{id}/events/stream — 流式接收响应（SSE）

来吧，让我们一起换一种方式构建 AI 应用。
